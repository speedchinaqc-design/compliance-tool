# 合规查询（本地，第一期）

给产品认证 / 合规工程师 Dan 自用的中文清单。第一期只做**欧盟、加拿大、美国**，样板产品是石田 UNI-8 计价贴标秤（非自动衡器，规划书写明准确度等级为**推断 III 级**；Wi-Fi；纽扣电池；已确认 FCC Part 15B Class A，另声明 IC RSS-102）。

页面在你自己的电脑上打开。没有后端，没有遥测。数据来自《合规查询小工具规划书 v3》里已经写明的格子，**不是法律意见**。规划书没写的，这里不加。

## 在自己的电脑上打开

克隆仓库之后可以离线使用。入口是登录页，不是清单页。

在仓库根目录运行：

```bash
python3 tools/serve.py
```

当前版本 **v1.3.3**。合规清单可以标「不做」，并和产品测试同步。每个产品都有 GEN-CB。照片可以从合规知识库里选。CB 页有履历。

v1.3.2：产品测试是由合规清单、文件模板和标签模板生成的待办。可以增加自定义清单条目。CB 证书记在 GEN/04ELEC_电气安全，用来对照已有的 62368-1 条目。基本信息顶部有产品信息总览。变体照片和铭牌照片、主型号缩略图都可以增加多张。

v1.3.1：打开工作区先进入产品档案。变体的屏幕尺寸是操作屏和客显屏的列表，也可以自填类型，并汇总成一行。档案首页的市场 × 模块可以筛选，导出汇总时可选筛选结果或全部。

v1.3 里，基本信息的型号变体是表格：变体型号、屏幕尺寸、每行 3 张照片路径。已填写的变体各自有状态、状态说明和 EU/CA/US 上市日期，产品状态汇总成全部已上市、部分已上市或未上市。标签与铭牌按变体列铭牌照片和标签信息。产品测试可以选「领导层决定先不做测试」，记下决定人和决定日期后，这一条不计入缺失证据。证据登记里的编号旁边会写出中文名称，文件名和导入仍用编号。

v1.2 的首页仍在：到期证据、差距或缺失、待核实、需要复核、最近备份。待分类里有文件也会提示。页面上方可以搜索，例如 UL 4200A 或 NAWI。法规来源有变化时，把每周检查议题里的 JSON，或 `docs/regulation-update-format.md` 里的文件，导入首页，相关行会标成「需要复核」。

当前安装包仍是 v1.1 的桌面程序。v1.2 的界面用浏览器打开本机服务即可。

v1.1 说明：当前版本曾为 **v1.1.0**。登录地址是 **<http://127.0.0.1:8765/login.html>** 。脚本会打印这个地址，并尝试用本机浏览器打开。服务只监听 `127.0.0.1`，局域网和公网都访问不到。按 Ctrl+C 停止。

账号和项目写在仓库旁的 `data_local/store.json`（不进 Git）。浏览器和桌面版共用这一份。旧的浏览器 localStorage 会在第一次连上服务时自动迁入。


## Dropbox 目录

默认根目录是 `%USERPROFILE%\Dropbox\合规知识库`，可在「备份与 Dropbox」里改。

- `00_工具备份`：自动备份
- `01_标准原文\OIML|EU|US|CA|CN`
- `02_产品\<型号>\EU|CA|US\` 下有 `01CYBER_网络安全`、`02PACK_包装`、`03DATA_数据安全`、`04ELEC_电气安全`、`05EMC`、`06RADIO_无线`、`07BATT_电池`、`08METRO_法制计量`
- `02_产品\<型号>\09_其他资料\通用|待分类|参考`。`_新产品模板` 里也有同样三格。待分类里有文件时，档案会提醒。参考目录不计入正式证据。文件名可以用市场 `GEN`、维度 `00GEN`，例如 `UNI-8_GEN_00GEN_RPT_CB12345_20260301_v1.pdf`（举例，不是真实报告）。
- `02_产品\<型号>\GEN\04ELEC_电气安全` 放 CB 证书和报告。CB 体系模块不新增法规。
- `02_产品\_新产品模板`：新建产品时按这个复制
- `03_法规动态\<年>`
- `04_模板\DoC|标签|申请表`
- `05_官方往来\CA_HealthCanada_26-005366-600`

路径旁边有「打开本地文件夹」和「在网页版 Dropbox 打开」。文件路径会打开它所在的文件夹。文件夹不存在时会先问再创建。工具只读取文件名、大小和修改时间。

请用当前仓库里的 `tools/serve.py`。它会给页面标明 `charset=utf-8`，并禁止缓存。中文 Windows 上如果脚本被当成 GBK，登录后会停在旧外壳、出不了产品列表。改完后先关掉原来的黑色窗口，再重新运行上面的命令。登录成功会进入产品列表，不是旧的筛选页。

第一次打开要设用户名和密码。设好后，清单在 <http://127.0.0.1:8765/index.html> ；没登录会被送回登录页。关掉标签页后要重新登录。页面上有「退出」和「重置本机密码」。

也可以双击 `login.html`。浏览器如果提供 WebCrypto，就可以在那里设密码；双击和 `http://127.0.0.1` 是两套浏览器存储，密码不互通。如果这个浏览器在 `file://` 下没有 WebCrypto，页面不会收密码，只提示改用上面的登录地址。

页面打开后不会自己去拉网页。法规链接只有在你点击时才会打开。

## 本机登录是隐私门，不是强安全

密码不会上传，仓库里也不保存密码。浏览器只用 WebCrypto 做加盐的 PBKDF2（SHA-256，210000 次），把用户名、盐和哈希放在这台浏览器的 `localStorage`。本次是否已登录放在 `sessionStorage`，关掉标签页就失效。

这挡的是别人随手打开页面。它挡不住这些情况：能操作这台电脑的人、能看这台浏览器网站数据的人、直接打开仓库里 YAML 的人。登录页上的「重置本机密码」只要确认就会清掉本机哈希、产品项目和进度，不需要旧密码。导出的 JSON 备份不受影响。不要把这份本地门当成账号系统或加密盘。

## 向导和工作区

登录后先看到产品列表。可以新建、按 UNI-8 样板新建、重命名、复制、删除。项目存在这台浏览器的 `localStorage`。用「导出 JSON」备份，文件可以放到 Dropbox；「导入 JSON」再读回来。重置本机密码会清掉这些项目。

每个产品走五步向导：

1. 选市场。第一期只有欧盟、加拿大、美国。
2. 选模块：电子产品、电池、CRA（网络安全与数据安全这一组）、FCC/ISED（美国无线和 EMC 授权、加拿大 ISED）、计量。模块只筛选矩阵里已有的格子。第一期没有单独的 RoHS 或 WEEE 行，工具不补写。
3. 问答：功能、材料、电压、Wi-Fi、纽扣电池及焊接/可拆、贸易结算、是否只走 B2B 登录渠道、是否处理个人数据。每题带依据和来源。电池题按 Health Canada 复函 26-005366-600：商用不自动豁免，焊接也不按豁免处理。
4. 按模块列出将放进工作区的文件模板、标签模板和组件。
5. 生成工作区。工作区有合规清单、模块、文件模板、标签模板、产品测试（含证书到期日）。页上固定写着：注意：您最终必须根据相关法律法规最新版本、指导文件或其他来源的要求采取行动。

模板只有骨架。需要你填写或核对的位置标为**待确认**。不要把付费标准原文写进模板或仓库。

## AI 判断结果导入

工具里没有 AI。请把说明书发给 Dan Bot，再把 Dan Bot 给出的 JSON 或 YAML 导入该产品的「AI判断结果导入」或档案里的对比清单。格式见 `docs/ai-judgment-format.md`。判断结果附在对应条目上，不改矩阵原文。状态可以是已核实、待核实、N/A、待确认。对比清单另用符合、差距、缺失。

## 产品管理档案

工作区里每个产品有「产品档案」。证据、照片、联系方式和证书都只记 Dropbox 路径和字段，工具不保存文件。

档案包括：基本信息（名称、主型号、变体表、各变体状态和上市日、照片路径或本机缩略图）、成本与供应商（商业敏感，审核包默认不含）、每条清单要求的证据类型、证据登记（编号加中文名称）、对比清单、市场×模块汇总（可导出 Excel，也可打印成 PDF）、标准版本与清单版本的对照、型号覆盖检查、90/30 天到期和法规文本里的日期、结论追溯到路径和页码、变更记录、按市场导出的审核包、关键件、按变体的标签与铭牌、说明书、责任主体、实验室进度和费用、问题与纠正、官方往来。

UNI-8 样板里的报告号、供应商和费用都写着「示例/待确认」，不是真实编号。Health Canada 复函只保留规划书里的编号 26-005366-600，并连到 CA-07。每月提醒由 Dan Bot 另外做，档案打开时会显示到期和过渡日期。

导出的项目 JSON 含整份档案。导入会按原样读回。

## 怎么用

1. 勾选市场：欧盟、加拿大、美国，可以多选。
2. 按产品属性筛选，例如：有没有 Wi-Fi、有没有纽扣电池、电池是焊接还是可拆、是否用于贸易结算、是否只通过要登录的 B2B 渠道销售、是否处理个人数据。
3. 三个视图：
   - **适用清单**：只列出当前属性下要看的条目。
   - **按市场**：每个已选市场的 8 个维度都在，不符合当前属性的会标成不进入清单，并写原因。
   - **按维度**：同一个维度并排看三个市场。
4. **导出 Excel**：在浏览器里生成 `.xlsx`，内容就是当前视图和筛选，含来源 URL 和 Dropbox 路径。不经过服务器。
5. **打印 / 存为 PDF**：调用系统打印。在对话框里选「另存为 PDF」或「Microsoft Print to PDF」。
6. 「已在这台电脑上标记看过」存在本机 `localStorage`，不会上传。换浏览器或清站点数据后标记会消失。

点「恢复 UNI-8 样板默认」回到样板属性：有 Wi-Fi、有纽扣电池、安装方式**未知**、用于贸易结算、不假设只做 B2B、不假设处理个人数据。

加拿大纽扣电池按规划书里的 Health Canada 复函要点显示（编号 26-005366-600，2026-10-16 收文）。复函非公开，**不在本仓库**。商用不自动豁免；只做 B2B 登录销售是建议，不是自动豁免。电池改成「焊接固定」时，页面会提醒：规划书里讨论焊接豁免的是澳洲，不能套到加拿大。

## 状态怎么读

每条都有规划书「强制性」栏的原文，另外有一个状态：

| 状态 | 含义 |
| --- | --- |
| 已核实 | 强制性栏里有 ✓ |
| N/A | 强制性栏里有 N/A（核实后没有针对性法规） |
| 待核实 | 栏里写了「待核实」，或者 ✓、待核实、N/A 都没有 |

没有打勾的格子**不会**被写成已核实。所以加拿大电气安全的强制性原文仍是「强制」，状态是「待核实」：规划书这一格没有 ✓。核实日期为空，是因为规划书没有逐格日期，不要填猜测的日期。

## 怎么改数据

市场文件：

- `data/EU.yaml`
- `data/CA.yaml`
- `data/US.yaml`

每个市场 8 个维度：网络安全、包装/EPR、数据保护、电气安全、EMC、无线 2.4/5 GHz、电池（纽扣）、法制计量。每条包含：法规名称、标准号、主管机构、强制性原文、认证路径、标签要求、来源 URL、核实日期、状态（已核实 / 待核实 / N/A）。

样板产品和筛选项在 `data/product.yaml`。Dropbox 里已经有的证书路径记在 `data/evidence.yaml`，只记路径和编号。

改完 YAML 后运行：

```bash
pip install -r requirements.txt
python3 tools/validate.py
```

校验通过后会重写 `js/data.js`。双击打开的页面读的是这个文件，所以要和 YAML 一起保留。只想检查、不写文件时：

```bash
python3 tools/validate.py --check
```

标准号必须出现在该条法规名称原文里；标签要求必须是法规名称或认证路径里的原文片段。这样是为了避免手滑写出规划书里没有的句子。

## Dropbox 路径

页面不连接 Dropbox，只按规划书第六节给出路径，方便你自己去文件夹里找证书和报告。

- 文件夹：`/合规知识库/02_产品/UNI-8/{市场}/{维度代码}/`

- 类型代码：`STD` 标准、`RPT` 测试报告、`CERT` 证书、`DOC` 符合性声明、`LBL` 标签、`CORR` 往来函件
- 矩阵键：`CA-07` 这种 `{市场}-{维度编号}`，用来和 `data/evidence.yaml`、Dropbox 里的 `index.xlsx` 对上

加拿大电池归档路径与规划书一致：`/合规知识库/02_产品/UNI-8/CA/07BATT/`。

不要给这些文件建共享链接。

## 每周检查来源页

`.github/workflows/source-watch.yml` 在默认分支上**每周一 02:00 UTC（北京时间 10:00）** 运行，也可以在 GitHub 的 Actions 页手动运行。

它读取三个市场 YAML 里的 `source_url`，抓取公开页面，对可见文字做规范化后取 SHA-256，和 `data/source-watch.json` 比较。有变化就开一条议题（或更新已经开着的那条），列出变了的网址。抓取失败或还没有基线的网址**不算**内容变化。

不需要在仓库里配置密钥。Actions 自带的 `GITHUB_TOKEN` 只用来开议题。

政府网站经常改页脚、会期或脚本，哈希变化不一定是法规变了。看到议题后打开链接自己确认，再改 YAML。有的官网对脚本返回 403、404，或先给浏览器校验页（例如 EUR-Lex）。这类结果**不会**写成基线，也不会每周各开一条议题。脚本能读到正文的页面才会进入比较；原先能读到、后来读不到，会写进议题。确认基线可以更新时，在本机：

```bash
pip install -r requirements.txt
python3 tools/check_sources.py --write-baseline
```

然后提交 `data/source-watch.json`。这个命令不会改法规 YAML，也不会把网页正文存进仓库。

## 不要提交这些东西

付费标准原文（EN、IEC、UL、CSA 等）只放在 Dropbox 私有文件夹。**不要**把标准 PDF、测试报告、证书、复函扫描件提交到本仓库，也不要写进网页。本仓库只保留标准号、条款号、来源 URL 和 Dropbox 路径。

校验脚本会拒绝仓库里的 `.pdf`、`.doc`、`.docx`、`.xls`、`.xlsx`、`.ppt`、`.pptx`。
